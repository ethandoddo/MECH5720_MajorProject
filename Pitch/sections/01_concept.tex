\vspace{0.4em}
\noindent\textbf{2. Goal.}
 \noindent To put a transmissive LCD in the optical path of a Canon DSLR so that software sets the aperture pattern for every frame. The requirement is a dynamic aperture, meaning the aperture pattern changes from one frame to the next. The test is two consecutive frames of a static scene with a different pattern on each, so the frames stay aligned to the pixel.

\vspace{\baselineskip}
 \noindent Once the gates pass, four secondary goals follow, all built from the dynamic aperture. The first is depth estimation. The two frames carry the patterns of a coded aperture pair [\rl{G6}] and a joint deconvolution of the pair recovers a depth map and an all-in-focus image. The second is post-capture refocus, which extends the capture to nine frames, each opening a different sub-aperture [\rl{G3}]. The third is custom bokeh, which repeats the dynamic aperture test with aperture shapes we design ourselves. The fourth is a flutter shutter, which switches the pattern within one exposure. Gate 3 measures whether the panel switches fast enough.

\vspace{\baselineskip}
 \noindent We found a hobbyist build that fits an LCD iris to a camera lens [\rl{G1}, \rl{G2}] and published research that uses controllable apertures for coded imaging [\rl{G4}, \rl{G5}]. Together they show that each part of this plan has been done before, so the risk lies in the integration rather than the concept.


\vspace{0.4em}
\noindent\textbf{3. Approach.}
A defocused point images as a scaled copy of the aperture. That holds only near the lens pupil, so mask position matters.
\begin{itemize}\setlength\itemsep{0pt}
    \item \textbf{Stage 1:} the panel sits against the front of the lens, near the entrance pupil. Edge points see a clipped pattern, so all tests use the image centre.
    \item \textbf{Stage 2}, only if Stage~1 passes all three gates: the panel moves into a slot cut in the 25\,mm extension tube, behind the exit pupil, where it starts to act as a light-field mask. The same patterns at both positions measure the difference.
    \item \textbf{Panel and control:} stripping the backlight and diffuser leaves the transmissive cell. A Raspberry Pi drives it over SPI and fires the shutter.
    \item \textbf{Processing:} a point source at 700, 1000 and 1300\,mm gives PSFs for the open disc and both coded patterns (Lab~3 protocol). Each image patch takes the depth whose PSF pair best explains both frames after Wiener deconvolution. Every capture set includes an open-disc control frame.
\end{itemize}

\noindent\textbf{4. Success criteria.}
\begin{itemize}\setlength\itemsep{0pt}
    \item \textbf{Gate 1, panel acts as an aperture:} a defocused point source matches the displayed pattern with normalised cross-correlation (NCC) $\geq 0.8$. Transmission loss stays at or below 3 stops.
    \item \textbf{Gate 2, coded pair PSFs:} PSF width grows with defocus. The two coded MTFs share no zeros in the target band, while the open-disc MTF shows its expected zeros.
    \item \textbf{Gate 3, dynamic aperture (the requirement):} two consecutive frames of a static point source show the two coded patterns at NCC $\geq 0.8$ each. Open-disc control frames before and after register within one pixel. The measured switching time decides whether a flutter shutter is possible.
    \item \textbf{Depth estimation, first application}, with textured targets at 700, 1000 and 1300\,mm: RMS depth error below 10\,\% of true distance. The all-in-focus image beats the open disc stopped down to the same depth of field on SSIM.
    \item \textbf{Post-capture refocus:} each target reaches peak SSIM against its in-focus reference at its true depth.
    \item \textbf{Custom bokeh:} every out-of-focus highlight reaches NCC $\geq 0.8$ against its displayed shape.
    \item \textbf{Flutter shutter}, only if the switching time allows a useful code in one exposure: deblurring narrows edge width on a moving target.
\end{itemize}

\noindent\textbf{5. Fallback.}
All validation captures at the front of the lens happen before the panel goes into the extension tube. If tube integration damages the LCD panel, those captures form the final deliverable and still address all four goals. If the measured switching time is too slow for a useful code within one exposure, the flutter shutter drops out and the deliverable is the other three goals. Depth estimation is the minimum deliverable, since it needs only two frames and the coded pair.
